# Accessibility Baseline

All UI produced by the factory must meet this baseline before station 12. The `code-reviewer` checks these items during auto-review (station 10).

---

## Radix Head-Start — Do Not Undo It

shadcn components are built on Radix UI, which provides:
- Keyboard navigation (arrow keys in menus/selects, Enter/Space for buttons)
- Focus trapping in modals and dialogs
- ARIA roles, states, and properties (`role="dialog"`, `aria-expanded`, `aria-labelledby`, etc.)
- Screen-reader announcements for dynamic content

Do not suppress, override, or work around these behaviors. If you find yourself removing a Radix prop to "fix" a visual issue, fix the visual issue a different way.

---

## Semantic HTML Requirements

| Use | Instead of |
|-----|-----------|
| `<button>` for clickable actions | `<div onClick>` or `<span onClick>` |
| `<a href>` for navigation | `<div onClick>` that calls `navigate()` |
| `<h1>`–`<h6>` hierarchy | All `<div>` with font-size classes |
| `<ul>`/`<ol>` for lists | `<div>` stacks |
| `<table>` for tabular data | CSS grid mimicking a table |
| `<nav>` for navigation regions | Unlabelled `<div>` with links |
| `<main>` for primary content | Unnamed outer wrapper |

---

## Landmark and Semantic HTML Table

| Landmark element | When to use |
|-----------------|-------------|
| `<main>` | Primary content area of a page (one per page) |
| `<nav>` | Navigation menus; add `aria-label` when multiple navs exist |
| `<header>` | Page or section header |
| `<footer>` | Page or section footer |
| `<aside>` | Secondary content (sidebars, callouts) |
| `<section>` | Thematic grouping with a heading |
| `<article>` | Self-contained content that makes sense in isolation |

## Labelled Controls

Every interactive control must have an accessible label. Use `useId` when multiple instances of the same form exist on a page.

```tsx
import { useId } from 'react'

export const ReasonField = ({ value, onChange, error }: ReasonFieldProps): JSX.Element => {
  const id = useId()
  const errorId = `${id}-error`

  return (
    <div className="flex flex-col gap-1.5">
      <label htmlFor={id} className="text-sm font-medium text-foreground">
        Reason
      </label>
      <textarea
        id={id}
        aria-describedby={error ? errorId : undefined}
        aria-invalid={!!error}
        value={value}
        onChange={onChange}
      />
      {error && (
        <p id={errorId} role="alert" className="text-sm text-destructive">
          {error}
        </p>
      )}
    </div>
  )
}
```

Rules:
- Use `htmlFor` + matching `id` — not `aria-label` alone (unless the label is truly invisible).
- Use `aria-describedby` to associate error messages with the field.
- Use `aria-invalid="true"` on fields in error state.
- Use `role="alert"` on error messages that appear dynamically.

## Form Accessibility Pattern (with shadcn)

shadcn `FormMessage` renders with `role="alert"` and automatically connects to the field via `aria-describedby`. Use it — do not roll custom error display.

## Keyboard Requirements

| Interaction | Required keyboard behavior |
|-------------|---------------------------|
| Button | Activatable with Enter and Space |
| Link | Activatable with Enter |
| Modal/Dialog | Opens with Enter/Space; closes with Escape; focus trapped inside |
| Select/Dropdown | Opens with Enter/Space; options navigable with arrow keys; closes with Escape |
| Tab order | Follows visual reading order; no keyboard traps outside modals |
| Focus visible | `:focus-visible` ring visible on all interactive elements |

Never remove `focus-visible:ring-2 focus-visible:ring-ring` from interactive elements.

---

## Contrast and Motion

- All text on colored backgrounds: minimum 4.5:1 contrast ratio (WCAG AA). Semantic tokens are pre-validated for this — do not replace them with lower-contrast custom values.
- Always pair animations with `motion-reduce:`:
  ```tsx
  <span className="animate-spin motion-reduce:animate-none" />
  ```

## Live Regions — Announcing Dynamic Change

A change a sighted user sees is a change a screen-reader user must hear. Anything that appears
without a page navigation needs a live region.

| Value | Behaviour | Use for |
|-------|-----------|---------|
| `role="status"` / `aria-live="polite"` | Announced at the next pause | Save confirmations, result counts, "3 items loaded" |
| `role="alert"` / `aria-live="assertive"` | Announced immediately, interrupting | Validation errors, session expiry, failed mutation |
| `aria-busy="true"` | Marks a region as loading | Skeleton containers while a query is pending |

```tsx
{isPending && <div aria-busy="true" aria-label={TextContent.LOADING_PROFILES}><ProfileSkeleton /></div>}
{isSuccess && <div role="status">{TextContent.PROFILE_DECLINED}</div>}
{isError && <div role="alert">{TextContent.PROFILE_DECLINE_FAILED}</div>}
```

Do not wrap the *whole page* in a live region — every re-render would be announced.

## Additional Baseline Requirements

- **Touch targets** ≥ 44×44 px on mobile breakpoints, including icon-only buttons.
- **Colour is never the sole signal.** A red border needs an icon or message beside it; a green
  "active" dot needs a text label.
- **Text resizes to 200%** without clipping — avoid fixed-height containers around text.
- **Skip-to-content link** at the top of the app shell, visible on keyboard focus.
- **Autocomplete** on known fields (`type="email" autocomplete="email"`).
- **`lang`** declared on `<html>`, and a descriptive `<title>` per route.

## Common Anti-Patterns

| ❌ Anti-pattern | Problem | Fix |
|---|---|---|
| `<div onClick>` as a button | Not focusable, no keyboard activation | Use `<button>` |
| Removing focus outlines | Keyboard users cannot see where they are | Style the ring, never delete it |
| Custom dropdown with no ARIA | Unusable by keyboard and screen reader | Use the shadcn/Radix `Select` |
| Empty link or icon button | Announced as "link", no description | Add text or `aria-label` |
| `tabindex` greater than 0 | Breaks natural tab order | Only `0` or `-1` |
| Missing `alt` | Image invisible to screen readers | Descriptive `alt`, or `alt=""` if decorative |
| Toast as the only error signal | Disappears before it is read | Also render the error inline, with `role="alert"` |

## Pre-Review Accessibility Checklist

The `code-reviewer` verifies these at station 10. UI engineers verify them before submitting work at stations 5–6.

- [ ] All clickable elements are `<button>` or `<a>` (no `div onClick` without `role="button"`)
- [ ] Every `<input>`, `<textarea>`, and `<select>` has a visible `<label>` connected via `htmlFor`/`id`
- [ ] Error messages use `aria-describedby` to associate with their field
- [ ] Fields in error state have `aria-invalid="true"`
- [ ] Dynamic error messages have `role="alert"`
- [ ] Modals trap focus and close on Escape
- [ ] All interactive elements have visible `:focus-visible` styles (do not set `outline: none` without a replacement)
- [ ] Tab order follows visual reading order
- [ ] Animated elements have `motion-reduce:` variants
- [ ] Images have `alt` text (empty string for decorative images: `alt=""`)
- [ ] Page has a single `<main>` landmark
- [ ] No hardcoded colors that bypass semantic token contrast guarantees
- [ ] Dynamic status and error messages sit in a live region (`role="status"` / `role="alert"`)
- [ ] Loading containers are marked `aria-busy` with a label
- [ ] State is never conveyed by colour alone
- [ ] Touch targets are ≥ 44×44 px at mobile breakpoints
- [ ] The feature was tabbed through by hand, not only scanned by axe
