# Template: navigation-js.md

**Superseded as a generation template** — `wire-nav.mjs`'s `navigationJs()` function
(`skills/generate-html/scripts/wire-nav.mjs`) is the actual generator now, and nothing reads this
`.md` file to produce output anymore. This file stays as a human-readable description of the
generated contract (active-page detection, `getPageTitle` / `getPageDomain` / `getPagesInDomain`
helpers) for anyone reading a generated prototype's `js/navigation.js`.

The example below shows the shape of what `wire-nav.mjs` writes — `PAGES` and `NAV_GROUPS` are
baked in as literals from `pages.json` / `nav.json`, not substituted into placeholders.

---

```javascript
// Multi-page navigation — active state + breadcrumb helpers.
// Generated by scripts/wire-nav.mjs — do not hand-edit; re-run wire-nav.mjs instead.

const PAGES = [
  { id: 'profiles-list', title: 'Profiles List', domain: 'profiles' },
  { id: 'profile-detail', title: 'Profile Detail', domain: 'profiles' },
]

const NAV_GROUPS = {
  profiles: ['profiles-list', 'profile-detail'],
  documents: ['documents-list', 'document-detail'],
}

// ── Active page detection ────────────────────────────────────────────
document.addEventListener('DOMContentLoaded', () => {
  const pathname = window.location.pathname
  const currentId = PAGES.find(p => pathname.endsWith(`/${p.id}.html`) || pathname.endsWith(`/${p.id}`))?.id

  if (currentId) {
    document.querySelectorAll(`[data-nav-id="${currentId}"]`).forEach(el => {
      el.classList.add('nav-item-active')
      el.setAttribute('aria-current', 'page')
    })
  }
})

// ── Helpers (available to inline Alpine expressions) ─────────────────
function getPageTitle(id) {
  return PAGES.find(p => p.id === id)?.title ?? id
}

function getPageDomain(id) {
  return PAGES.find(p => p.id === id)?.domain ?? ''
}

function getPagesInDomain(domain) {
  return PAGES.filter(p => p.domain === domain)
}
```

---

## Where `PAGES` / `NAV_GROUPS` actually come from

`assembly-wiring` writes `pages.json` (`[{id,title,domain,description}]`) and `nav.json`
(`{domain: [pageId,...]}`), then runs `wire-nav.mjs --dir ... --pages pages.json --nav nav.json`,
which bakes those straight into `PAGES` / `NAV_GROUPS` as literals in the generated
`js/navigation.js`. The order of domains in `nav.json` determines the visual order in the sidebar
nav; the order of IDs within each domain array determines page order within the group.
