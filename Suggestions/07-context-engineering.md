# 07 — Context engineering

The quality of every spoke's output is bounded by the **signal density** of its context. The factory treats context as an engineered, budgeted resource — not as "whatever the agent happens to read".

Two problems to solve:

1. **Per-dispatch context** must be small, relevant and reproducible.
2. **Context cost must not grow with the app.** Every merged feature makes the repo bigger; if agents discover the codebase by grepping, cost and duplication grow linearly.

## Three circles, three temperatures

| Layer | Content | Loaded | Owner | Stability |
|---|---|---|---|---|
| **Hot** | `CLAUDE.md` constitution (< 150 lines), always-on rules (honesty, security) | every session, automatically | factory-core | very stable |
| **Warm** | path-scoped stack rules, skills, golden files, `app-profile.yaml`, capability slices, ADR index | when the task touches matching paths / when the pack names them | stack packs, Cartographer | changes with architecture |
| **Cold** | ADR bodies, ledger history, incident notes, old specs | only on explicit request (rung 3 diagnosis, change requests) | ledger | archival |
| **Ephemeral** | the context pack: task, ACs, exemplars, feedback | one dispatch | Context Broker | discarded after the task |

Rules of thumb:

- If it applies to every task, it's hot — and it must be short.
- If it applies to a class of tasks, it's a path-scoped rule or a skill — never `CLAUDE.md`.
- If it applies to one task, it belongs in the pack — never in a permanent doc.

## Capability index

The Cartographer maintains a mostly machine-generated map of the app, regenerated **after every merge** (and before planning when stale).

| File | Generated by | Used by |
|---|---|---|
| `capability-map.yaml` | route/module scan + haiku summary | analyst (what exists), architect, planner |
| `component-inventory.yaml` | AST parse: path, props digest, capabilities, usage count | architect, planner (reuse checks), builders |
| `patterns.md` | pattern detectors → pointer to golden file / skill | builders, reviewer |
| `mock-catalog.yaml` | fixture scan | prototyper, test authors |
| `slices/<domain>.slice.md` | composed from the above per domain (1.5–4k tokens) | every pack, T1 |
| `index.meta.json` | git SHA + timestamp | Conductor refuses to plan on a stale index |

```yaml
# component-inventory.yaml (excerpt)
- name: DataTable
  path: src/shared/ui/DataTable
  props_digest: "columns, rows, onSort?, selection?, emptySlot?"
  capabilities: [sort, paginate, row-selection, empty-state]
  used_by: 11
  golden: patterns.md#tabular-data
  do_not_fork: true            # extend via props; forking fails review
```

Properties that matter:

- **~90% deterministic** (AST, route tables, import graph) and ~10% cheap summarisation → regenerating takes seconds.
- **Scale-invariant**: the repo can grow 10×, but an agent reads one slice, not the repo.
- **Frozen during a feature**: the index SHA is stamped into the feature's state; it is not regenerated mid-feature, so all spokes of a feature see the same world.

## Context packs

Every dispatch is driven by a **materialised file**, not an ad-hoc prompt. It is deterministic, cacheable, reviewable — and the first thing to read when debugging "why did the agent do that?".

```markdown
---
pack_id: FEAT-021/TASK-007/a2
role: frontend
agent: fe-builder
budget_tokens: 45000
read_allowlist_max: 12
index_sha: 9f2c1ab
---

## T0 — Mission (always, ~600 tok)
Feature FEAT-021 · Stage implementation · Task TASK-007 · Attempt 2/3
Satisfies: AC-0901, AC-0902
Files you may write: src/features/apply-coupon/ui/CouponField.tsx (+ colocated test)
DoD: <verbatim from tasks.yaml>
Exit gate (run it yourself): factory gate impl FEAT-021 TASK-007
Return: envelope schema v1

## T1 — Orientation (always, ~2.5k tok)
Feature digest:     .factory/features/FEAT-021/digest.md          [READ]
Capability slice:   .factory/_index/slices/checkout.slice.md      [READ]
Reuse decision:     shared/ui/Input + shared/ui/InlineError (reuse)
Patterns in force:  patterns.md#form-field, patterns.md#mutation-hook

## T2 — Specification (paths only — read what you need)
ACs:        .factory/features/FEAT-021/02-stories/stories.yaml#STORY-0230
Contract:   .factory/features/FEAT-021/03-architecture/api-contract.yaml#applyCoupon
Golden files (match these):
  - src/features/apply-promo-banner/ui/PromoField.tsx
  - src/features/apply-promo-banner/ui/PromoField.test.tsx

## T3 — Attempt feedback (only on retry)
Previous gate: eslint(2) jsx-a11y/label-has-associated-control
Progress: 4 → 2 failures (improving) · fingerprint a91f (new) · rung 1
Instruction: fix ONLY the reported violations. Do not refactor.

## T4 — On demand (counted)
Up to 12 additional reads, each reachable from the slice or the golden files.
Unscoped Grep/Glob is blocked.
```

### What each role's pack contains

| Role / stage | T1 slice | T2 extras | Deliberately withheld |
|---|---|---|---|
| requirements-analyst | capability map, ledger (brownfield) | normalised context | code, architecture |
| planner | slice, inventory | stories, component map, contract | code bodies |
| fe-builder | one slice | ACs, contract op, 2 golden files | other features' specs, full PRD |
| acceptance-test-author | — | ACs, test plan, contract | **all of `src/`** |
| reviewer | slice | diff, ACs, ADRs touched, golden files | builder's reasoning / envelope summary (avoids anchoring) |
| qa-engineer | — | stories, ACs, UX notes, charters | **all of `src/`** |
| prototyper | slice, mock catalog | stories, UX notes | architecture, contract, ADRs (keeps it from drifting into implementation) |

## Budgets

```yaml
context:
  budgets:                  # tokens per dispatch
    conductor:         20000   # guard this hardest
    analysis_roles:    60000   # analyst, architect, planner
    execution_roles:   45000   # builders, test authors
    review_roles:      35000
    prototype_role:    30000
  read_allowlist_max: { execution_roles: 12, prototype_role: 8 }
  rules:
    pass_paths_not_payloads: true
    unscoped_search: blocked
    return_summary_max_words: 200
```

Enforced at four points:

1. **Construction** — the Broker refuses to emit an over-budget pack; it drops T2 exemplars first and marks `context_degraded: true` (a metric, see [12](12-observability-and-evals.md)).
2. **Runtime** — a `PreToolUse` hook counts reads per spoke; past the allowlist it blocks with "declare why you need this file".
3. **Return** — a `SubagentStop` hook rejects envelopes that are too long or miss fields.
4. **Authoring** (static) — `npm run validate` keeps today's read-budget tripwire: agent prompt + always-loaded references ≤ a fixed line budget per agent.

## Prompt-cache-friendly ordering

Spokes of the same kind share a long, stable prefix: agent prompt → rules → skill → golden files → *then* the pack's volatile T0/T3. Parallel dispatches of the same agent type (e.g. five verification lenses) therefore hit the cache. Volatile content never goes first. (Kept from app-dev-kit's prefix-cache optimisation.)

## The Conductor's own context

The Conductor reads only: config, a **brief view** of `state.json`, the pending envelope(s), and gate verdicts. It never opens source files or artifact bodies. Target: < 20k tokens at all times. In headless mode each `/factory:next` starts with a fresh context anyway.

- After compaction, a `SessionStart` hook (`compact` matcher) re-injects `factory state --brief` and the open human notes. The Conductor keeps nothing in its chat that isn't on disk, so compaction loses wording, never decisions.
- `factory state --brief` prints only what the next decision needs: current stage, ready tasks, pending gate, budgets left, last verdicts (≤ 3k tokens). The full `state.json` grows with every task; re-reading it each turn made the Conductor ~30% of a feature's tokens in the walkthrough ([15](15-walkthrough-and-estimates.md#revision-pass--bottlenecks-found-and-fixes-applied)).
- Independent dispatches (parallel lenses, two build lanes, a pipelined red phase) go out in **one** turn, which cuts Conductor turns per feature by about a third.

## Curator digests

At the stage exits whose digest is read downstream (S1, S4, S6 by default), the `curator` compacts `changelog.md`, decisions and gate history into `digest.md` (≤ 800 tokens) — the cheap, always-current T1 summary for downstream stages.

It must never drop a tracked ID. The ID-coverage checker (a script) rejects a digest unless every open REQ, AC, decision (ADR), open question (OQ) and human note (HD) from its sources appears in it — in full or as a one-line reference with the source path. A digest is navigation, never the source of truth: packs always list the full artifacts by path in T2.

## Where context can be lost, and what catches it

Pipeline context lives in files, not in any agent's conversation, so nothing depends on a chat surviving. What remains is a short list of places where information could still be dropped:

| Where | Risk | What prevents it | What detects it |
|---|---|---|---|
| Conductor session | compaction during a long run | reads only brief state + envelopes; `SessionStart` hook re-injects state after compaction; headless runner starts each step fresh | Conductor turn and compaction counts in `events.jsonl` |
| Spoke context | a task too large for its budget | ≤ 45k-token pack, ≤ 12 reads, tasks ≤ 3 files / 200 LOC; a hung or overflowing spoke is restarted from its pack, not from a summary | wall-clock and budget rules ([09](09-quality-gates-and-loop-control.md#detection-rules)) |
| Middle of a long context | instructions buried and ignored | small packs; stable prefix first, mission / ACs / feedback last | first-pass gate rate per agent |
| Envelope (≤ 200 words) | builder's summary leaves things out | summaries are never an input for correctness: `artifacts_written` lists paths; reviewer and QA don't see summaries at all | gates run on files, not on summaries |
| Digest (≤ 800 tokens) | curator drops a requirement or decision | full artifacts listed by path in every pack | ID-coverage checker rejects the digest |
| Pack trimming | Broker drops T2 exemplars to fit the budget | trimming order is fixed; ACs, DoD and contract are never trimmed | `context_degraded: true` on the event |
| Stage → stage | a stage forgets an upstream ID | typed artifacts with schemas; `stage.yaml` declares `tracked_ids` | `gate-plan` (every AC → test), `gate-docs` (every AC in the feature doc), PR trace table |
| Chat with the human | an instruction given only in chat | instructions become `HD-*` notes (below) | `gate-plan` and `gate-ready-for-pr` require every open note to be resolved |

The principle: **detect loss by ID, don't trust memory.** Every requirement, AC, decision, open question and human note has an ID, and scripts check that each one reaches the stage that needs it. A lost item fails a gate instead of quietly disappearing. GT-12 ([12](12-observability-and-evals.md#layer-3--golden-tickets-headless-with-models)) tests this end to end.

### Human instructions are artifacts

Anything you say to the factory that changes the work is stored before it is acted on:

- `/factory:gate approve|reject "<notes>"` writes the notes as `HD-*` entries;
- `/factory:note "<text>" [--feature FEAT-021]` adds one at any time between gates;
- the Conductor refuses to act on a chat instruction that has no `HD-*` entry — it records it first, then continues.

```yaml
# features/FEAT-021/human-notes.yaml
- id: HD-3
  at: GATE-A
  by: artsiom
  text: "Hide the coupon field for guest users."
  status: open                 # open → mapped → done | declined
  mapped_to: []                # filled by the analyst or planner: [REQ-0912, AC-0915, TASK-011]
```

A note is open until the requirements-analyst or planner maps it to a REQ / AC / task, or a human declines it. `gate-plan` fails while any note made before GATE-B is unmapped, and `gate-ready-for-pr` fails while any note is still `open`.

## Anti-patterns this design removes

| Anti-pattern (seen in practice) | Replacement |
|---|---|
| 25 KB of references loaded per builder spawn | T2 lists paths; builder reads ≤ 12 files |
| Same station order described in three files | pipeline defined once in config; agents don't restate it |
| Pasting contracts into prompts | contract op referenced by path + anchor |
| Instructions that live only in the chat | `HD-*` notes in `human-notes.yaml`, checked by gates |
| Trusting a summary to carry requirements | summaries are navigation; IDs are checked by script |
| Whole-board reads | per-task pack (successor of work cards) |
| Rules attached to every `.ts` file | rules scoped to the role's `owns_paths` |
