# i18n (react-i18next) — review checklist

Distilled from the `i18n` skill. Applies to any new or changed user-facing string, date/number/
currency formatting, or plural/RTL handling.

- A hardcoded user-facing string, including `aria-label`, `alt`, `title`, `placeholder` — not passed through `t()`.
- A translation key assembled at runtime instead of a static literal (unless every variant is enumerated in a typed `as const` map).
- A key that isn't hierarchical/specific (`emptyState` instead of `users.list.emptyState`), or nests past three levels.
- String concatenation for interpolation instead of `t('greeting', { name })`.
- A manual `count === 1 ? ... : ...` plural branch instead of the `count` option with `_one`/`_other` suffixes.
- Copy with embedded markup or a link split into concatenated fragments around JSX instead of one key rendered with `<Trans>`.
- A hand-built date/number/currency format, or a formatter constructed fresh per render, instead of a memoized `Intl.*` formatter built from the active locale.
- Physical Tailwind utilities (`ml-`, `mr-`, `left-`, `right-`) in layout that should be RTL-safe, instead of logical ones (`ms-`/`me-`, `ps-`/`pe-`, `text-start`, `start-`).
- A new key added only to a translated locale file, with no corresponding entry in the same change to the default locale JSON.

## Severity

A hardcoded user-facing string or a missing default-locale entry is **Must fix** (the `i18n`
constraint is treated as a hard rule). Formatter/RTL/`<Trans>` misses are **Should fix**.
