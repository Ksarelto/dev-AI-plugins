# Scaffold a service

## When to use

- Starting a new backend service, API or microservice in this stack
- Re-creating the boilerplate tree in an empty repository
- Not for adding endpoints to an existing service — that is `express-resource`

Hard constraints: `rules/stack.mdc`, `rules/layered-architecture.mdc`, `rules/typescript-node.mdc`. The reference implementation is `backend-boilerplate/` at the root of the dev-AI-plugins marketplace repo. Its tree, scripts and dependencies are in [references/tree.md](references/tree.md); the bootstrap files (`index.ts`, `app.ts`, `server.ts`, `container.ts`, `config/env.ts`, configs) are in [references/core-files.md](references/core-files.md); the reference `users` slice is in [references/users-slice.md](references/users-slice.md).

## Procedure

1. **Get the source.**
   - Marketplace repo available (local clone, or the user names its path): copy the folder without build output.
     `rsync -a --exclude node_modules --exclude dist --exclude coverage --exclude .env <marketplace>/backend-boilerplate/ <target>/`
   - Not available: create the tree from [references/tree.md](references/tree.md). Take each file's code from the skill that owns it (column "Code in" of the tree table). Do not improvise a file the table does not list.
2. **Rename.** Replace `backend-boilerplate` with the service name (kebab-case) in:

   | File | What |
   |---|---|
   | `package.json` | `name`, `description` |
   | `docker-compose.yml` | top-level `name:` |
   | `src/lib/logger.ts` | default logger `name` |
   | `src/config/env.ts` | `JWT_ISSUER`, `JWT_AUDIENCE` defaults |
   | `.env.example` | `JWT_ISSUER`, `JWT_AUDIENCE` |
   | `src/openapi/document.ts` | `info.title` (and `tests/integration/health.test.ts`, which asserts it) |
   | `.github/workflows/ci.yml` | `docker build -t <name>:ci` |
   | `README.md` | title and intro |

   Then `grep -rn backend-boilerplate --exclude-dir=node_modules .` must print nothing except `package-lock.json` (regenerated in step 4).
3. **Environment.** `cp .env.example .env`. Generate a real `JWT_SECRET` (`node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`). Never commit `.env`.
4. **Install.** `nvm use` (Node 22, `.nvmrc`) → `npm install`.
5. **Database.** `npm run db:up && npm run db:migrate`. Optional: `npm run db:seed` for the admin user from `SEED_ADMIN_*`. If 5432 or 3000 is taken, set `DB_PORT` / `API_PORT` and update `DATABASE_URL`.
6. **Verify.** `npm run typecheck && npm run lint && npm run test`. The integration project needs Docker (Testcontainers); for Rancher Desktop or Colima set `DOCKER_HOST` and `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE` (`api-testing` skill).
7. **Run.** `npm run dev` → `curl localhost:3000/health/ready` → docs at `/api-docs`.
8. **Remove what the service does not need**, in the same change, with its tests: e.g. the auth routes when an external IdP issues tokens (`auth-rbac` skill), the `UPSTREAM_HEALTH_URL` check, the seed. Run step 6 again.
9. **First resource.** Continue with the `express-resource` skill.

## Do not

- Do not `npm init` a fresh project and re-add libraries one by one; versions and config in the boilerplate are verified together.
- Do not swap a stack library (see `rules/stack.mdc`) while scaffolding.
- Do not delete `.dependency-cruiser.cjs`, the `unit`/`integration` Vitest projects, or the CI workflow.

## Checklist

- [ ] Copied without `node_modules`, `dist`, `coverage`, `.env`
- [ ] No `backend-boilerplate` string left outside `package-lock.json`; lockfile regenerated by `npm install`
- [ ] `.env` created from `.env.example` with a fresh ≥ 32-char `JWT_SECRET`; `.env` is git-ignored
- [ ] `npm run db:up && npm run db:migrate` succeeded
- [ ] `npm run typecheck`, `npm run lint`, `npm run test` (unit + integration) pass
- [ ] `/health/live` and `/health/ready` answer 200 from `npm run dev`
- [ ] Unused features removed together with their tests and docs entries
